# GITTELLER 1.0.8-dev — автономное поручение Grok

## Цель

Не ещё один GitHub-клиент с красивыми карточками, а **недорогое, приватное, нативное Android-приложение**, которое помогает неспециалисту понять: **что реально изменилось в проекте, что ещё неизвестно и почему это важно**. Без обязательной платной модели/облачного сервера. Пользователь должен суметь пользоваться продуктом после разовой покупки; стоимость будущей дистрибуции не следует путать с бесплатностью каждого API.

Продолжай из `gitteller/`, сначала зафиксируй дерево и SHA-256 исходников. Не начинай заново. Пакет содержит реальную версию с патчем предыдущего аудита, а **исходный APK 1.0.7 не включает этот патч**.

### P0. Достоверность событий GitHub, без ложных итогов

**1. Сопоставление задач и PR.** Убрать модель `изменение = смена state`. Ввести типизированные события или эквивалент, которые умеют различать:
- новая открытая задача/PR;
- закрытие, повторное открытие;
- изменение заголовка и `updated_at` (редактирование описания показывать как «запись обновлена», если его содержание не загружено);
- изменение `merged_at` или `merged` как самостоятельный факт слияния PR, отдельно от `closed`;
- отсутствие элемента из-за неполной загрузки ≠ удаление;
- удаление/недоступность сущности не выводить из разницы неполных выборок.

Сохранить `number`, `title`, `state`, `updated_at`, `merged_at` и признаки полноты по источникам. Для PR подтверждать `merged_at` через GitHub и при необходимости детальным запросом PR. Никакого `closed = merged`. Добавить тесты на 4 исходных RED, а также reopen, обновление описания, частичную пагинацию, отсутствие исходного baseline. Следить, чтобы счётчики включали правильные события, но не выдавались за количество доказанно исправленных функций.

**2. История веток.** Не называть любое изменение SHA «прогрессом». Для изменившейся ветки, выбранной пользователем или входящей в ограниченный список приоритетных, запрашивать `GET /repos/{owner}/{repo}/compare/{oldSHA}...{newSHA}`. Обрабатывать `ahead`, `behind`, `diverged`, `identical`, `404/409`, большие сравнения и обрезку `files`/`commits` по ограничениям API. `ahead` с новыми коммитами → «появились новые записи»; `behind` → «история откатилась»; `diverged` → «история изменилась, нельзя трактовать как обычное продвижение»; недостаточно данных → «неизвестно». Новая ветка, которой не было в полной прошлой проверке, обозначается как «впервые обнаружена между снимками», не гарантированно только что создана. Для публичного проекта работает без токена.

**3. Связь события с доказательством.** Для каждого объяснения сохранять: тип события, ID (`repo/issue#/PR#/SHA`), timestamp источника, URL GitHub (только `https://github.com/` данного репозитория), конкретные файлы/проверки при наличии, признак полноты и происхождение (`LIVE`, `CACHED`, `IMPORTED`, `PARTIAL`). Каждое пользовательское утверждение должно быть привязано к реальному полю источника. При отсутствии данных «не проверено», а не угадывание по названию ветки, `fix:` или `[skip ci]`.

**4. Экспорт/импорт.** В `SnapshotCodec` сохранять разрешённые, необходимые для сравнения поля `merged`, `merged_at`, `updated_at` и новые флаги полноты; whitelisting обязателен. Исключать токены, `Authorization`, patch/body с потенциальными секретами и любые неизвестные поля. Проверить round-trip и защиту от подмены/импорта: файл извне никогда не превращается в «свежий подтверждённый GitHub».

### P0. Сеть и безопасность

**5. Не устраивать DDoS своему лимиту GitHub.** На главной — одна экономная синхронизация с ограниченным числом запросов, `ETag`/`If-None-Match` там, где работает, явное распределение по источникам. Подробности и compare — только по интересующим веткам и по запросу. Ограничение времени/повторов, `Retry-After`, rate-limit headers, пользовательская кнопка повтора после ошибки, возможность отменить; изменения не затирают последние достоверные данные. `403` не всегда неверный токен. Checks недоступны для fine-grained PAT — показывать доступные Commit Statuses/Actions, а не просить новый PAT. Не запускать Actions.

**6. Хранилище токена.** Не менять Android Keystore + AES-GCM и привязку к repo. Исправить риск удаления прошлой рабочей записи при `renameTo` failure: использовать безопасную атомарную замену (`AtomicFile` или обоснованный эквивалент) с гарантией «ошибка записи → прежний токен читается», включая сбой между записью и фиксацией. Любая временная запись — только ciphertext в `noBackupFilesDir`. Проверять что `hasToken` не означает успешную дешифровку. Реальный PAT не использовать в тестах. Отдельные синтетические тесты: перезапуск, `force-stop`, смена репозитория, повреждённый контейнер, отказ записи, миграция debug APK без потери данных. Никаких `pm clear` и удаления приложения владельца.

**7. Неполные данные.** Все источники хранить с собственными временем обновления, полнотой и stale-флагом. Если `issues` не обновились, но ветки обновились, нельзя показывать все данные как полностью свежие. При импорте/частичном ответе не делать вывода «всё готово», «нет проблем», «ничего нового». Пагинация списков обязана иметь ограничение и признак неполноты.

### P0. UX для человека, не читающего код

**8. Главная страница.** Один короткий обзор: «Что изменилось» (максимум 2 человеческие строки), «Что требует внимания» (одна главная проблема/нехватка доказательств), «Что сделать дальше» (одна обоснованная кнопка). Полные SHA, `403`, JSON, сырые английские заголовки — только в «Технических деталях». Отдельно видимый **статус синхронизации с датой**, причём частичный срез не называется полной успешной проверкой. Никаких недоказанных процентов готовности.

**9. Полноэкранные страницы:** обзор, изменения (таймлайн событий), направления (ветки), задачи, PR, надёжность данных, подключение и настройки. Навигация стандартная: выбор элемента → подробная страница → стрелка Back и системный Back возвращают на предыдущую. Длинные названия не рушат вёрстку, список прокручивается, нет огромных системных диалогов, темы светлая/тёмная, крупный шрифт Android, TalkBack content descriptions. Язык интерфейса — русский (дальнейшие языки отдельным этапом). Никакого HTML/WebView.

**10. Объяснения:** обязательный формат каждой записи:
- **Событие:** что произошло (русским языком).
- **Основание:** например, задача #7 поменяла `open → closed`, PR #5 получил `merged_at`, в ветке N добавились 3 коммита или поменялись документы.
- **Не подтверждено:** выполнение тестов, работоспособность функции, готовность на Android.
- **Подробнее:** ссылка на оригинал GitHub, исходные технические поля и время.
При явно частичной загрузке — не «не было», а «не удалось проверить». На уровне дизайна отделить проблему сети от проблемы кода и от ещё не пройденной приёмки.

### P1. Коммерчески полезное после P0

**11. Лента событий за последние проверки:** локальная история хотя бы 10–30 снимков на проект (с ограничением размера и без секретов), дедупликация событий, фильтры «Все / Новое / Проверки / Задачи / Слияния», ссылки на доказательства. Не терять историю при смене проекта или перезапуске. Измерить размер хранения и производительность на A52; SQLite/Room вводить только при необходимости.

**12. Пользовательское управление:** добавить/переключать несколько проектов без смешивания их данных и токенов; понятная диагностика подключения «репозиторий виден / нет прав / лимит / сеть», отдельный справочный экран «почему нельзя доказать готовность по коммиту». Ручной экспорт понятного краткого отчёта через Android Share/текст, без публикации приватных данных без отдельного действия владельца.

### Не делать в этой версии

- Не строить самописную LLM/облачную платную аналитику.
- Не вводить новую архитектуру или тяжёлые зависимости без показанного выигрыша.
- Не обещать GitHub OAuth/App или публикацию в Play без отдельных решений владельца: это следующий этап коммерциализации.
- Не подменять «Готово» красивыми эвристиками названий файлов, веток или числом коммитов.
- Не раздувать главный экран и не копировать весь репозиторий на телефон.

### Работа и полномочия

Можешь самостоятельно исправлять и тестировать GitTeller. Не трогай репозиторий UNO, его `main`, GitHub Actions и другие проекты. Не удаляй пользовательские данные, не делай force-push, не отправляй токены и приватную историю в отчёты или сторонние сервисы. Любая операция с GitHub — GET/READ ONLY.

Не задавай владельцу вопросов, которые можно разрешить исходниками, GitHub-документацией и тестами. Если реальное решение владельца обязательно — сформулируй один конкретный блокер. Сохраняй контрольную точку и возможность отката.

### Результат

Передать ZIP исходников, собранный и подписанный debug APK, `versionCode >= 23`, SHA-256 APK и исходного ZIP, сертификат подписи (сверить с 1.0.7), `CHANGELOG`, исходные и новые Gradle tests/XML, отдельные локальные tests, эмуляторные скриншоты всех экранов и Back, список непройденных проверок и инструкцию обновления поверх 1.0.7 без удаления данных. Впереди независимая приёмка и живой тест на A52: не выдавать до неё `DEVICE_VERIFIED`.

**Результат нужен работающий, а не очередная переименованная заготовка.**
