# GitTeller — планы развития (черновик)

Дата решения о направлении: 2026-11-17. Основная Android-ветка: `feat/ads-help-1.0.14`. Никаких сроков релиза этот документ не обещает.

## Подтверждено владельцем как направление

- Основной Android-продукт распространяется бесплатно и содержит рекламу.
- Следует поддержать русский и английский языки.
- Распространение не ограничивать одним магазином, рекламную монетизацию не привязывать навсегда к единственной сети.
- Позже планируется платный вариант без рекламы.
- Позже планируется версия для ПК.

**Ни один пункт выше не означает, что соответствующая функция реализована или приложение уже опубликовано.**

## Предложения, требующие отдельного решения владельца

- Третий язык: испанский (`es`). Аргумент: широкая аудитория нескольких стран.
- Четвёртый кандидат: португальский для Бразилии (`pt-BR`).
- Для ПК первой целевой платформой рассмотреть Windows. Поддержку иных ОС решить отдельно.
- Для Android рассмотреть RuStore, Google Play, Huawei AppGallery и официальный сайт. Это список кандидатов, не подтверждение доступности аккаунтов, платёжных инструментов или допуска к публикации.

## Этап 1. Готовность Android к публикации

- Закончить текущие исправления, запустить тесты, собрать APK с исходной подписью и проверить обновление без потери данных на Samsung Galaxy A52.
- Подготовить политику конфиденциальности и честное описание работы с GitHub, токеном и рекламой.
- Проверить актуальные правила выбранных магазинов, доступность регистрации разработчика и рекламных выплат в соответствующих странах.
- Проверить доступность GitHub API, ошибки сети, лимиты, восстановление после отказов, экспорт/импорт.
- Реклама не должна перекрывать основные действия. Продумать согласие и управление приватностью, где это требуется.

## Этап 2. Локализация

- Перенести пользовательские строки в ресурсы Android, не меняя сохранённые токены, снимки и схему данных.
- Поддержать `ru` и `en`; третий язык `es` только после утверждения владельца. `pt-BR` — следующий кандидат.
- Проверить все экраны, меню, системные ошибки, уведомления, даты, длину строк и доступность элементов.
- Отдельно вычитать материалы «От разработчика»: машинный перевод не должен незаметно менять позицию или признания автора.
- Язык устройства использовать по умолчанию; ручное переключение — предполагаемое поведение, требует реализации и тестов.

## Этап 3. Распространение и рекламные сети

- Подготовить описание, скриншоты, юридические сведения и подписанные артефакты отдельно для каждого магазина.
- Текущая интеграция в коде: Yandex Mobile Ads 7.18.1. Другие сети сначала оценить по совместимости, правилам, региональной доступности, конфиденциальности и фактическим условиям выплат.
- Не добавлять новый SDK только ради числа рекламных партнёров. Токены GitHub не отправлять рекламным сервисам.
- Зафиксировать понятные идентификаторы версий, неизменность подписи и способ обновления вне магазина.

### Рекламные блоки Яндекса перед релизом (обязательная задача)

**Текущее состояние подтверждено по исходникам (2026-11-17):**
- `app/src/main/java/app/unocontrol/AdUnits.java`: `BANNER = "demo-banner-yandex"`, `INTERSTITIAL = "demo-interstitial-yandex"`, `DEMO = true`.
- `app/src/main/java/app/unocontrol/Ads.java` уже запрашивает баннеры и межстраничную рекламу.
- `app/build.gradle`: SDK `com.yandex.android:mobileads:7.18.1`.
- Это демонстрационные блоки, за показы которых доход не начисляется. Настоящие ID **ещё не предоставлены**.

**Действие владельца (в кабинете РСЯ):**
1. Зарегистрировать собственный аккаунт на https://partner.yandex.ru/apps ; персональные данные, пароли и платёжные реквизиты остаются у владельца.
2. Добавить Android-приложение GitTeller с точным пакетом `app.gitteller.mobile`. Если ещё не опубликовано, добавить как неопубликованное в тестовом режиме.
3. Создать два рекламных блока соответствующих форматов: Banner и Interstitial. Получить два индивидуальных ID вида `R-M-XXXXXXX-X`; не использовать пример как рабочее значение.
4. После публикации указать ссылку на магазин, подтвердить владение через поддерживаемый метод, пройти модерацию и настроить реквизиты выплат в кабинете. Проверить все актуальные требования РСЯ.

**Действие Codex после получения обоих настоящих ID:**
1. Заменить демо-ID в релизной конфигурации, но сохранить возможность безопасных тестовых показов при разработке. Не смешивать тестовые и боевые идентификаторы и не считать `DEMO = false` доказательством запуска реальной рекламы.
2. Проверить баннеры, межстраничную рекламу, частотный лимит, скрытие пустого рекламного слота, корректный возврат после закрытия и обновление GitHub без рекламного блока.
3. Проверить отсутствие утечек Activity и сетевых секретов, SDK-инициализацию, сообщения YandexAds в Logcat, фактическую работу с реальными ID только когда это допустимо по правилам РСЯ.
4. Собрать подписанный APK и проверить на Samsung Galaxy A52. До реального испытания считать статус `NOT_DEVICE_VERIFIED`. Не объявлять рекламу монетизируемой без активного приложения и подтверждения в кабинете РСЯ.

Документация: https://ads.yandex.com/helpcenter/ru/quick-start и https://ads.yandex.com/helpcenter/ru/monetization/app/add .
**Не заменять демоблоки выдуманными ID и не запускать GitHub Actions.**

## Этап 4. Вариант без рекламы

- Ввести платный вариант позднее, после принятого решения о конкретной модели оплаты.
- Предполагаемый принцип: те же основные функции, но без рекламы. Разовую покупку можно рассмотреть, она пока не утверждена.
- До реализации проверить правила покупок соответствующего магазина, восстановление права на версию и границы совместимости между магазинами.
- Покупки, аккаунты и лицензирование сейчас **не реализованы**.

## Этап 5. ПК-клиент

- Сделать отдельное приложение для компьютера с теми же принципами: чтение GitHub, ясное происхождение данных, отсутствие неподтверждённых выводов.
- Android Views нельзя напрямую переносить на ПК; сначала определить переносимые компоненты логики и независимый интерфейс.
- Целевая ОС, способ публикации и модель монетизации ПК-версии требуют отдельного решения. Windows — предложение, не обязательство.
