# Changelog

## 1.0.12-dev (versionCode 27)

- На главном два режима одних и тех же данных: «Режим чайника» и «Режим разработчика». Выбор пишется в `gitteller_v1` ключом `display_mode`. По умолчанию режим чайника. Неизвестный ключ тоже остаётся режимом чайника. Токен и снимки не трогаются.
- В режиме чайника прежние четыре ответа. «Подробнее» открывает раздел. «Почему так?» показывает правило вывода и не называет коммит проверкой, задачу дефектом или автора работающим агентом.
- В режиме разработчика — сводка веток, ленты, задач, PR, проверок и выборочной истории. Частичный, устаревший и импортированный снимок подписаны. Новых запросов GitHub нет.
- Технические поля на карточке подробностей в режиме разработчика видны сразу. В режиме чайника их по-прежнему нужно открыть.

## 1.0.11-dev (versionCode 26)

- Импорт исключён из наблюдений о сдвиге веток и из базы запроса сравнения указателей.
- Ошибка загрузки последних коммитов отмечает снимок как PARTIAL. Отчёт учитывает старые снимки без признака успешной загрузки истории.
- Объяснение события «ветка обнаружена» указывает на текущий снимок и предыдущий полный список.
- Экран направления показывает подтверждённое различие двух SHA при неполной загрузке веток.
- Добавлено 13 регрессионных тестов, включая запросы GitHub с подставными HTTP-ответами и проверку метода экрана направления.

## 1.0.10-dev (versionCode 25)

- Главный экран — выбранный `owner/repo`, время загрузки, база сравнения и один статус: данные загружены, часть недоступна, есть изменения или нет достоверного сравнения. Кнопки «Обновить» и «Сменить проект».
- Четыре коротких ответа: что изменилось, где работа, какие проблемы, кто выполнял. Карточка открывает соответствующий раздел.
- Сдвиг указателя ветки больше не звучит как «появились новые записи» и не показывает SHA. Текст говорит, что файлы ещё не запрашивались. Сравнение `ahead` / `behind` / `diverged` по-прежнему только при открытии направления.
- `updated_at` без текста описания: запись обновлена, содержание неизвестно. Это не «исправлено».
- Проблемы разделены: подтверждённых ошибок проверок в общем снимке нет (пустота не успех), название с дефектом или блокировкой — только предположение, обычная задача так и называется. Не каждая Issue — баг.
- Исполнитель — автор последней записи основной ветки в GitHub, если он есть в снимке. Иначе «не установлен». Grok, Codex и «сейчас работает» не выводятся из имени ветки или коммита.
- Лента: что произошло, где, откуда известно, что это значит, что не проверено. Повтор «Не подтверждено: Не подтверждено» убран. SHA остаётся за «Показать технические сведения».
- Разделы: Обзор, Изменения, Направления, Проблемы — первыми. Задачи, предложения, история, надёжность, доступ и настройки сохранены. На каждом экране видно имя проекта. Системная Back и стрелка назад на месте.
- Влиты исправления аудита 1.0.9.1 после собственного RED: известный сдвиг ветки виден и при неполном списке; новое имя на фоне полного прошлого списка не прячется с главной; откат указателя не называется новыми записями; отсутствие имени в двух полных списках даёт событие «не обнаружено», не «удалено».
- Безопасность токена, `allowBackup=false`, только HTTPS и только `INTERNET` не менялись. `User-Agent`: `GitTeller/1.0.10-dev`.

## 1.0.9-dev (versionCode 24)

- ETag первой страницы больше не считается полным списком. Он сохраняется только если у ответа GitHub нет `rel=next`. Старый снимок без признака `issuesEtagSinglePage` (и таких же для веток и предложений) условный запрос не получает: отфильтрованный короткий список задач мог скрывать вторую страницу.
- Замена токена — один атомарный `move` в том же каталоге. Если процесс умер после старого `rename` в `.bak`, следующий запуск возвращает этот шифртекст на место. Если атомарная замена недоступна, запись отклоняется и прежний файл не стирается. На Android Keystore это не проверялось.
- Повтор того же события (ветка снова сдвинулась, задача снова открылась) остаётся в ленте. Одинаковый текст больше не выбрасывается навсегда.
- Изменение номера, который есть в обоих снимках, видно даже при неполном списке. Номер, которого не было в неполной выборке, по-прежнему не называется новой или удалённой записью.
- Появление и переименование записи не называются «сменой статуса». Сдвиг исследовательской ветки не называется продвижением: это может быть откат или переписывание истории.
- SHA и сырые поля на карточке скрыты, пока не нажато «Показать технические сведения».

## 1.0.8-dev (versionCode 23)

- Новая задача, смена названия, правка `updated_at` и слияние PR считаются изменениями, даже если SHA веток и поле `state` не сдвинулись. Закрытие по-прежнему не называется слиянием и не называется готовностью.
- Исчезновение номера из неполного списка не называется удалением. Если номера нет в обоих полных списках, лента говорит только, что его нет в новой выборке.
- Для открытого направления с другим указателем запрашивается `GET /compare/{old}...{new}`: впереди, откат, расхождение, совпадение или «Недостаточно данных». Откат не называется прогрессом. Ошибка сравнения не стирает снимок.
- Лента до 30 событий на проект: событие, основание, что не подтверждено, ссылка `https://github.com/` этого репозитория. Фильтры: все, новое, проверки, задачи, слияния. Проверок в ленте нет, пока GitHub их не отдал отдельным фактом.
- Первая страница полного короткого списка веток, задач и предложений может уйти с `If-None-Match`. Ответ 304 не называется новой полной историей. Списки длиннее одной страницы по ETag не кэшируются: страница 2 может измениться при той же первой странице.
- Замена токена пишет временный файл и ставит его на место через запасную копию. Если установка не удалась, читается прежняя запись. Наличие файла не называется успешной расшифровкой.
- Импорт помечается `IMPORTED` и не становится базой для «живого» прогресса. В архиве сохраняются `merged`, `merged_at` и `updated_at`. Секреты и неизвестные поля по-прежнему выбрасываются.
- Главный экран остаётся коротким: не больше двух фраз о событии, без SHA. Частичный срез не называется полной проверкой.

## 1.0.7-dev (versionCode 22)

- Сравниваются указатели всех загруженных веток, а не только последний коммит `main`. Сдвиг `research/*` при неподвижном `main` описывается отдельно. Первая проверка не называется сравнением.
- Неполный список веток, задач или предложений не выдаётся за полную картину. Если раздел не обновился, остаётся прошлый список и ставится пометка, что он не свежий.
- Ошибки GitHub разделены: 401, 404, 403 без прав, 403/429 с лимитом. Лимит не повторяется сразу. Тайм-аут показывается по-русски. Старый снимок при полном сбое не затирается. Токен при ошибке сети не удаляется.
- Проверки: сначала check-runs, затем статусы коммита, затем GitHub Actions для того же SHA. Пустой ответ, `skipped` и `neutral` не называются успехом.
- Главный экран: что изменилось, что требует внимания, следующий шаг, кнопка «Обновить», дата последней удачной загрузки и покрытие. SHA и сырой HTTP с главного экрана убраны.
- Отдельные экраны: обзор, направления, история, задачи, предложения, надёжность, подключение, настройки. У записи: что произошло, что известно, чего нельзя установить, источник и технические детали с копированием.
- Закрытый запрос изменений не называется внесённым без отметки GitHub. `[skip ci]` не считается проверкой. Префикс ветки — предположение по названию.

## 1.0.6 (versionCode 21)

- Пустой или оборванный список задач и предложений больше не выглядит как «ноль записей».
- Смена статуса задачи при тех же SHA веток видна на главном экране и не называется готовностью.
- Старый снимок без признака полноты не сравнивается как полный.
- Неполный список не подписывается фразой «новых сдвигов нет».
- Экран задачи, предложения и коммита запрашивает одну запись GitHub: текст, файлы, check-runs. Нет ответа — «Недостаточно данных».
